# 運用ガイド（公開のしかた・日常の更新）

## 全体の流れ

```
Google スプレッドシート（選手 / 試合）
        │  ← 運営メンバーが入力
        ▼
GitHub Actions（毎朝5時 / 手動 / push のとき）
  1. スプレッドシートを CSV で取り込む
  2. サイトを作る
  3. GitHub Pages に公開する
```

取り込みやビルドに失敗した場合は、公開されずに前回のサイトが残ります。

---

## 1. 初回セットアップ（1回だけ）

### 1-1. GitHub にリポジトリを作る

- GitHub で新しいリポジトリを作る（名前の例：`saitama2nd-hp`）
- **Public（公開）にする**（GitHub の無料プランでは、Pages は公開リポジトリのみ）

### 1-2. ロックファイルを作ってコミットする（重要）

公開用の仕組みは、`package-lock.json` が無いと動きません。パソコンで `npm install` を実行すると自動で作られるので、**これも一緒にコミット**してください。

### 1-3. GitHub に上げる

VS Code の「ソース管理」から、または次のコマンドで上げます（`<…>` は自分の値）。

```bash
git init
git add .
git commit -m "first commit"
git branch -M main
git remote add origin https://github.com/<アカウント名>/<リポジトリ名>.git
git push -u origin main
```

### 1-4. Pages の公開元を設定する

GitHub のリポジトリで **Settings → Pages → Source** を **GitHub Actions** にします。

### 1-5. 公開を確認する

**Actions** タブで「Deploy to GitHub Pages」が緑のチェックになれば完了です。公開先は
`https://<アカウント名>.github.io/<リポジトリ名>/` です（`astro.config.mjs` の `site` と `base` は、GitHub 上では自動で決まります）。

## 2. スプレッドシートをつなぐ（1回だけ）

### 2-1. スプレッドシートを作る

シートを 2 枚作り、名前を「選手」「試合」にします。**1行目の列名は、下の表のとおりに（1文字も変えずに）**書いてください。
`data/players.csv` と `data/matches.csv` を、Google スプレッドシートの「ファイル → インポート」で読み込むと、雛形になります。

**「選手」シート**

| 列名 | 入力する内容 |
|---|---|
| 表示順 | 並べたい順の数字（1, 2, 3…） |
| 名前 | 表示する名前 |
| 背番号 | 数字（空欄でも可） |
| ポジション | GK / DF / MF / FW など |
| 写真 | 写真のファイル名（例：`tanaka.jpg`）。空欄なら代替画像 |
| 表示 | ○ で表示、× で非表示（行を消さずに隠せる） |

**「試合」シート**

| 列名 | 入力する内容 |
|---|---|
| 日付 | `2026-11-03` の形（年-月-日） |
| 対戦相手 | チーム名 |
| 会場 | グラウンド名など |
| 大会名 | 例：南部支部1部リーグ 第7節 |
| 自チーム得点 | 試合後に入力。空欄なら「日程」として表示 |
| 相手得点 | 試合後に入力（自チームとセットで入れる） |
| メモ | キックオフ時間など（任意） |

### 2-2. シートを CSV で公開する

パソコンのブラウザで対象のスプレッドシートを開き、次の操作をします。公開できるのは、そのファイルを編集できるアカウントです。

1. メニューから **ファイル → 共有 → ウェブに公開** を開きます。
2. ダイアログ上部の **リンク** タブを選びます（「埋め込む」ではありません）。
3. 左側のプルダウン（最初は **ドキュメント全体** と表示）を開き、**選手** を選びます。
4. 右側の形式のプルダウンで **カンマ区切り形式（.csv）** を選びます。
5. **公開** を押し、確認画面が出たらもう一度 **OK／公開** を押します。
6. ダイアログに表示された公開 URL をコピーし、メモ帳などに「選手」と分かるように控えます。ブラウザのアドレス欄にある編集用 URL や、通常の **共有** ボタンの URL ではありません。
7. 左側のプルダウンを **試合** に切り替え、形式が **カンマ区切り形式（.csv）** であることを確認して、同じように **公開** を押して URL を控えます。確認画面が出た場合も、もう一度 **OK／公開** を押します。
8. それぞれの URL をブラウザの新しいタブで開き、CSV の文字列またはダウンロードされた CSV が表示されることを確認します。先頭行が列名になっていれば OK です。ログイン画面やスプレッドシートの編集画面が出る URL は使えません。

すでに公開済みの場合は、ダイアログの **公開済みのコンテンツと設定**（または同等の表示）を開き、リンクタブで対象シートと CSV 形式を選んで URL を確認します。シートの内容を変更したあと、公開内容への反映に時間がかかることがあります。

> ⚠ 公開した URL を知っている人は、誰でも中身を見られます。**連絡先・住所などの個人情報の列は、このスプレッドシートに作らないでください。**（サイトに載せる内容だけを入れます）

### 2-3. GitHub に URL を登録する

リポジトリの **Settings → Secrets and variables → Actions → Variables タブ → New repository variable** で、2つ登録します。

| 名前 | 値 |
|---|---|
| `SHEET_PLAYERS_CSV_URL` | 「選手」シートの URL |
| `SHEET_MATCHES_CSV_URL` | 「試合」シートの URL |

### 2-4. 反映する

**Actions** タブを開き、左側のワークフロー一覧から **Deploy to GitHub Pages** を選びます。ワークフローの画面右上にある **Run workflow** を押し、ブランチに `main` が選ばれていることを確認して、もう一度 **Run workflow** を押すと実行されます。Actions の最初の一覧画面では、このボタンは表示されません。

## 3. 日常の更新

| やりたいこと | やり方 |
|---|---|
| 選手を追加・編集 | 「選手」シートに行を足す・書き換える |
| 選手を載せなくする | 「表示」を × にする（行は消さない） |
| 試合の日程を追加 | 「試合」シートに行を足す（得点は空欄） |
| 試合結果を入れる | 該当の行の「自チーム得点」「相手得点」を入れる |
| すぐ反映したい | Actions タブ → Deploy to GitHub Pages → Run workflow |
| 待てるなら | 毎朝5時（日本時間）に自動で反映される |

> Google 側の公開内容が更新されるまで、数分かかることがあります。反映されないときは、少し待ってから Run workflow をやり直してください。

### 選手の写真を追加する

1. 写真を、縦横 1000px 程度に縮小しておく（重いとサイトが遅くなる）
2. GitHub のリポジトリで `public/images/players/` を開く
3. **Add file → Upload files** で画像をドラッグ＆ドロップして、Commit する
4. 「選手」シートの「写真」列に、ファイル名だけを入れる（例：`tanaka.jpg`）

> 写真を載せてよいか、本人に確認を取ってから追加してください。

## 4. 困ったとき

Actions タブで赤い ✗ が付いたら、その実行をクリックして、「build」の中の赤いメッセージを読みます。

| メッセージの例 | 原因と対処 |
|---|---|
| `「日付」は 2026-11-03 の形で入力してください` | 日付の書き方が違う。表示された行を直す |
| `次の列名がありません` | シートの1行目の列名が違う。上の表どおりに直す |
| `CSV ではなく HTML でした` | 公開の形式が違う、または公開されていない。2-2 をやり直す |
| `HTTP 404` | URL が違う。2-3 の URL を見直す |
| `package-lock.json` に関するもの | 1-2 のロックファイルをコミットしていない |

失敗した間も、前回のサイトは公開されたままです。

## 5. 知っておくこと

- 結果を入れ忘れたまま日付が過ぎた試合は、「これからの試合」からは消えます（結果を入れると、「試合結果」に出ます）。
- 公開リポジトリで **60日間まったく動きがない**と、GitHub が毎朝の自動実行を止めることがあります（GitHub の仕様。詳しくは GitHub のドキュメントで確認してください）。止まったときは、Actions タブから再開できます。
